# Remote Solve — Design Spec

> **Status:** design, pre-implementation.
> **Scope:** a phone-friendly way for the human to solve an *escalated* interactive challenge (captcha) in the agent's **live browser session**, delivered over Telegram, so the user is never tied to the desktop. The agent waits for the human's solve and resumes — it never solves the challenge itself.
> **Fits:** a component of the Human-Loop Router (the Telegram phase). Depends on Phase 1's `gate_probe` (detection) and `HANDLERS` (`escalate`).

---

## 1. Problem & boundary

Phase 1 detects interactive gates (hCaptcha/reCAPTCHA-v2 checkbox/image) and routes them to `escalate` — currently "stop and report." The user is mobile and answers via Telegram, so "walk to the Mac and solve it" doesn't work. Remote Solve delivers the **live browser** to the phone so the human can solve the one step by hand, then the agent continues in the same session.

**Hard boundary (unchanged from the parent design):** this is a *human* solving a challenge in a *real* session, delivered remotely. It is **NOT**:
- a captcha solver or classifier,
- mouse-movement / behavioral mimicry to appear human (that is bot-detection evasion — out of scope, the user's own seam),
- token relay/farming to any third-party service.

The agent's role is strictly: hold the session, show it to the human, forward the human's taps, detect the human's solve, resume. No synthetic input is ever generated by the agent.

## 2. Flow

```
gate=escalate (interactive)
  → keep the headed session alive (LangGraph interrupt(); checkpointer persists the run)
  → RemoteSolveSession.start(page):
        start CDP screencast on the page
        spin a local live-view server (frames out / taps in) bound to the Tailscale iface
        mint a single-use, expiring, secret URL
  → human_loop("remote_solve", {url, gate, deadline}) → Telegram card with the link
  → user taps link ON PHONE → sees live frames → solves challenge with thumb
        taps → CDP Input.dispatch* into the real page (human input, forwarded verbatim)
  → poll is_cleared(page): challenge-response token becomes non-empty
        → tear down the view, invalidate the URL
        → Command(resume) → graph continues to submit/next step
  timeout / abort → run stays parked (checkpointer); re-notify or human aborts
```

## 3. Components

### 3.1 CDP bridge (`browser/live_view/cdp_bridge.py`)
- `start_screencast(page, on_frame)` — opens a CDP session (`page.context.new_cdp_session(page)`), `Page.startScreencast` (jpeg, capped width/quality), forwards each `Page.screencastFrame` to `on_frame` and acks it.
- `forward_pointer(cdp, x, y, kind)` — maps a normalized viewer coordinate `(0..1, 0..1)` to page pixels and dispatches `Input.dispatchMouseEvent` (mousemove/mousedown/mouseup) — **carrying the human's tap**, nothing synthesized.
- `stop_screencast(cdp)` — `Page.stopScreencast` + detach.
- The bridge never generates input on its own; it only relays events that arrive from the viewer.

### 3.2 Live-view server (`integrations/live_view/server.py`)
- Tiny `aiohttp` app: one WebSocket route.
  - Server→client: base64 jpeg frames + the page's current viewport size.
  - Client→server: pointer events `{x, y, kind}` (normalized) → `cdp_bridge.forward_pointer`.
- Serves a minimal **mobile-first** HTML page (touchstart/touchend → normalized pointer events; a `<canvas>`/`<img>` painting frames). No external assets.
- Binds to the **Tailscale interface address**, never `0.0.0.0`/public. One concurrent viewer per session.

### 3.3 Session & URL (`integrations/live_view/session.py`)
- `RemoteSolveSession`:
  - `start(page) -> str` — creates the CDP screencast + server, mints URL `https://<tailnet-host>:<port>/s/<token>`, returns it.
  - `wait_until_cleared(timeout_s) -> bool` — polls `gate_probe.is_cleared(page)` at ~1s until the challenge token appears or timeout.
  - `close()` — stops screencast, closes server, invalidates token.
- **Token:** ≥256-bit `secrets.token_urlsafe`, **single-use** (consumed on first WS upgrade), **TTL** (default 300s), bound to this one page. Second use or post-TTL use → 404/close. Only one active session at a time.

### 3.4 Exposure / tunnel
- **Default: Tailscale.** The server is reachable only on the user's tailnet (their Mac + their phone). No public internet exposure. Uses the Tailscale IP / MagicDNS host; nothing is published to the world.
- **Fallback (opt-in only): cloudflared/ngrok** — public URL, therefore requires the token *and* is discouraged; gated behind an explicit `REMOTE_SOLVE_ALLOW_PUBLIC=1`. Never the default.
- Config: `TAILSCALE_HOST` (or auto-detect via `tailscale ip -4`), `REMOTE_SOLVE_PORT`, `REMOTE_SOLVE_TTL`, `REMOTE_SOLVE_ALLOW_PUBLIC`.

### 3.5 Resume detection (`gate_probe.is_cleared`)
- Reuse Phase 1 signals: the challenge writes a response token — `textarea#g-recaptcha-response` (reCAPTCHA) or `textarea[name="h-captcha-response"]` (hCaptcha) — becoming non-empty on a successful human solve. `is_cleared(page)` returns True when the relevant token is populated (or `classify_gate` returns `cleared`/`none`).

### 3.6 Human-Loop Router integration
- New kind: `human_loop("remote_solve", {url, gate, deadline})` → Telegram message: the challenge type, the tap-to-solve link, a countdown, and an **Abort** button. On solve the agent posts "✅ cleared, continuing." On timeout: "⏳ still blocked — resend link / abort?".

## 4. Security model (the link controls a logged-in browser)

The live-view URL is effectively remote control of a browser inside the user's candidate session — treat it as a credential.

- **Tailnet-only by default.** Not reachable from the public internet; only the user's own devices.
- **Single-use + short TTL.** Consumed on first connect; expires (default 5 min); dies on solve/abort.
- **Unguessable.** ≥256-bit token in the path; server binds to the tailnet iface, not a public one.
- **One viewer, one session.** No concurrent viewers; a second escalation mints a fresh session.
- **No persistence.** Frames are streamed, never written to disk; nothing is logged with frame content.
- **Public tunnels are opt-in and flagged**, never default; when enabled, the token is the only gate, so TTL is shortened.
- **Privacy:** frames may show data the user already entered — it stays on the tailnet, unseen by any third party, consistent with the local-first posture.

## 5. Failure modes

| Failure | Behavior |
|---|---|
| User never solves (timeout) | Run stays **parked** via the checkpointer; Telegram offers resend/abort. Nothing submitted. |
| Challenge failed (token never appears) | `wait_until_cleared` returns False → re-notify; do not proceed. |
| Tunnel/Tailscale down | `start()` raises a clear error → escalate degrades to Phase-1 "stop and report" (safe fallback). |
| Browser/page crash | Session `close()`; run parked; human notified. |
| Second use of a spent link | Rejected (404); the real session is untouched. |

## 6. Non-goals / later

- Image-challenge ergonomics tuning on small screens (usable, not optimized).
- Multi-viewer / screen-sharing, session recording.
- Any automated solving, input synthesis, or third-party solver — permanently out of scope.

## 7. Global constraints

- **Human-in-the-loop only:** every pointer event originates from the user's device; the agent synthesizes none.
- **No evasion:** no mouse-dynamics modeling, no detection-scoring manipulation, no token relay.
- **Private by default:** tailnet-only; public exposure is an explicit, flagged opt-in.
- **Safe degradation:** if remote solve can't start, fall back to Phase-1 escalate (stop + report) — never auto-proceed past a gate.
- File hygiene < 500 lines; tests under `tests/career_agent/`, never root.

## 8. Testable surface (for the plan)

Pure/unit (no browser, no network):
- token: entropy length, single-use consumption, TTL expiry, one-active-session invariant.
- coordinate mapping: normalized `(0..1)` → page pixels for a given viewport.
- `is_cleared`: token-present → True; absent → False (extends Phase-1 gate signals).
- URL builder: tailnet host + token path; public-exposure guarded by the flag.

Integration (skip-marked, `RUN_BROWSER_TESTS=1`):
- CDP screencast round-trip on a local fixture with a fake `h-captcha-response` field: start session → simulate a viewer pointer event that sets the token via page script → `wait_until_cleared` returns True → `close()` tears down.
- expired/second-use link rejected end to end.
