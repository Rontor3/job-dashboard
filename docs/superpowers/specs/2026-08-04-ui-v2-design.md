# Dashboard UI v2 — Design

**Date:** 2026-08-04
**Status:** Approved (design), pending spec review
**Depends on:** existing React dashboard (App.jsx, Overview, FilterBar, Feed, JobDetail), `jobs.status` column, `company_classifications`, `PATCH /api/jobs/{id}/status`

## Goal

Restructure the dashboard into a **two-tab app** (Browse + Tracker) with a
**warm/dark theme toggle** and a reskin, so the candidate can both discover jobs
and manage applications through stages. Insights is explicitly deferred.

## Non-goals

- No **Insights** tab / charts (separate future feature).
- No new job data — reuses `jobs.status` and the existing classification chips.
- No router library — tab state is local component state.
- No drag-and-drop **library** — the board uses **native HTML5 drag-and-drop**
  (`draggable` + `onDragStart`/`onDragOver`/`onDrop`), zero new dependencies.

## Architecture

Additive to the current single-page app. `App.jsx` gains a **tab switcher**
(Browse / Tracker) and a **theme toggle** in the header; the `<main>` renders one
tab at a time. Five focused pieces:

1. **Theme system** — `styles/tokens.css` gets a `:root[data-theme="dark"]`
   override block; a `ThemeToggle` sets `document.documentElement.dataset.theme`
   and persists to `localStorage`. All components already consume `var(--…)`, so
   no per-component color edits.
2. **Tab shell** — `App.jsx` header: title, tabs, theme toggle, refresh. `activeTab`
   state (`"browse" | "tracker"`), default `browse`.
3. **Browse tab** — reworked `Overview` (fit tiles + clickable industry bar) +
   existing `FilterBar` + `Feed` (cards gain a **Track** control).
4. **Tracker tab** — new `TrackerBoard` + `TrackerCard`, fed by `GET /api/tracker`.
5. **Status wiring** — Track / move-stage / untrack via `PATCH /api/jobs/{id}/status`.

## Theme system

`tokens.css` keeps the current `:root` (Warm — the default). Add:

```css
:root[data-theme="dark"] {
  --canvas:#1E2229; --card:#262B34; --hairline:#333A44;
  --green:#7FD1B9; --green-mid:#5FB49C; --green-soft:#4E9683; --green-tint:#2F3A34;
  --ink:#E8EAED; --ink-soft:#A9B0BA; --ink-faint:#6B7280;
  --warm-band:#262B34; --ring-track:#2B313B; --card-2:#2B313B;
  --hover-shadow:0 2px 10px rgba(0,0,0,0.35);
  /* gold/peach/dupe kept but muted for contrast on dark */
}
```

`ThemeToggle`:
- On mount, read `localStorage.theme` (`"warm"` default) → set
  `document.documentElement.dataset.theme` (attribute absent = warm).
- Toggling swaps warm↔dark, writes `localStorage`, updates the attribute.
- A sun/moon control in the header (reuse `icons.jsx` pattern).

Contract: default (no attribute) = today's warm look, byte-for-byte unchanged.

## Tab shell (App.jsx)

- `const [activeTab, setActiveTab] = useState("browse")`.
- Header row: **Job dashboard** title + live `stats` line · centered tabs
  (**Browse** | **Tracker**) · **ThemeToggle** · **RefreshButton**.
- `<main>`: `activeTab === "browse"` → `<Overview/> <FilterBar/> <Feed/>
  <DuplicatesSection/>`; `=== "tracker"` → `<TrackerBoard/>`.
- `JobDetail` overlay works from either tab (selected id).
- Refresh reloads whichever tab is active.

## Browse tab

**Overview** (reworked):
- **Fit tiles:** `Strong` and `Good` counts (from `stats`; extend the stats
  endpoint to include verdict counts if not present).
- **Top-industries mini-bar:** the top N industries with counts (from a new
  `/api/classifications/summary` or folded into stats), each a **clickable**
  segment that sets `filters.industry`. Reuse the chip styling.

**FilterBar:** unchanged (search · Industry ▾ · Company-type ▾ · Sort ▾), already shipped.

**Feed card:** unchanged layout + a **Track control**:
- Job not tracked (`status` null / not a tracker stage) → **`+ Track`** button →
  `PATCH status="saved"`, then refetch.
- Job already tracked → shows its **current stage** (e.g. "Saved ✓" / "Applied")
  as a small label instead of the button.
- Dismissed jobs remain excluded from Browse (existing behavior).

## Tracker tab

**`GET /api/tracker`** → `{ saved:[…], applied:[…], interviewing:[…], offer:[…],
archived:[…] }`, where each list is jobs at that `status`, carrying the same feed
fields (title, company, chips, score, id). `archived` = `status="rejected"`.

**TrackerBoard:** four columns — **Saved · Applied · Interviewing · Offer** — each
with a header count; below the board a collapsed **Archived** section
(`rejected`). Empty columns show a muted placeholder.

**Drag-and-drop (native HTML5):** each `TrackerCard` is `draggable`; on
`dragstart` it stashes the job id (`dataTransfer`). Each column is a drop target
(`onDragOver` preventDefault + a highlight, `onDrop` reads the id) → `PATCH
status=<column stage>` → refetch board. Dragging is the primary way to move a
card across the four active columns. No DnD library — plain handlers.

**TrackerCard:** title, company, industry/company-type chips, score badge, plus a
small **⋯ menu / `<select>`** that is (a) the keyboard-accessible fallback for
stage moves and (b) the home for the two non-column actions:
- any stage value → `PATCH status=<stage>` → refetch (same as a drop).
- **Reject** → `PATCH status="rejected"` → card moves to Archived.
- **Remove from board** → `PATCH status=""` (clears to null; job returns to the
  untracked Browse pool). Requires the status endpoint to accept an empty value
  as "clear"; the DB helper sets `status = NULL`.
- Clicking the card body (not the drag) opens `JobDetail`.

## Data & API

- **Status vocabulary** on `jobs.status`: `saved · applied · interviewing · offer
  · rejected` (plus existing `dismissed`). Tracker stages are the first four;
  `rejected` → archived; `dismissed` stays hidden everywhere; `null` = untracked.
- **`PATCH /api/jobs/{id}/status`** (exists) — used for Track, move-stage, reject,
  and untrack. Extend `set_job_status`/endpoint to accept an empty/`null` value to
  clear the column (untrack) if it does not already.
- **`GET /api/tracker`** (new) — `tracker_jobs(conn)` in db.py: selects jobs with
  `status IN (saved,applied,interviewing,offer,rejected)`, LEFT JOIN
  `company_classifications` (same fields as the feed), grouped in Python by
  status into the five buckets.
- **Fit counts + industry summary** for the Overview — extend `dashboard_stats`
  to include `verdict_counts` (Strong/Good/…) and `top_industries`
  (`[{industry,count}]`, top ~6), or add a small `/api/overview` endpoint. One
  round-trip either way.

## Error handling

- Theme: unknown/absent `localStorage.theme` → warm default; toggling never throws.
- `/api/tracker` failure → board shows an inline error, Browse unaffected.
- A `PATCH` failure → surface the error, leave the card where it was (refetch
  reconciles).
- Empty board / empty column → muted placeholder, not a crash.

## Testing

**Frontend (Vitest):**
- Tab switch renders Browse vs Tracker content.
- ThemeToggle sets `data-theme`, persists to localStorage, and re-reads it on mount.
- **+ Track** on a Browse card calls `PATCH status="saved"` and the card then
  shows the tracked stage.
- `TrackerBoard` renders jobs into the correct columns from a mocked
  `/api/tracker` payload; archived section lists `rejected`.
- A column's `onDrop` (with a `dataTransfer` carrying a job id) calls `PATCH`
  with that column's stage — the drag path, tested via the drop handler (jsdom
  has no real drag, so fire `drop` with a stubbed `dataTransfer`).
- The fallback menu: a stage change calls `PATCH` with the chosen status;
  **Reject** calls `PATCH status="rejected"`; **Remove from board** calls
  `PATCH status=""`.
- Industry-bar segment click sets the industry filter.

**Backend (pytest):**
- `tracker_jobs` groups jobs by status into the five buckets, carrying chips.
- `GET /api/tracker` returns the grouped shape.
- `set_job_status` clears to `NULL` on empty input; existing status behavior
  unchanged.
- `dashboard_stats` (or `/api/overview`) returns `verdict_counts` +
  `top_industries`.

## Global constraints

- React + Vite + Vitest; Python 3.11 + FastAPI + pytest; every file under 500 lines.
- **Warm theme is the default and pixel-unchanged** when no `data-theme` is set.
- No new frontend dependency (no router, no DnD lib).
- Reuse existing seams: `PATCH /api/jobs/{id}/status`, `set_job_status`,
  `query_jobs`/classification join, `dashboard_stats`, `icons.jsx`, the token
  variables, and the existing Overview/FilterBar/Feed components.
- A job is never lost: untrack clears status to null (returns to Browse), it is
  not deleted.
