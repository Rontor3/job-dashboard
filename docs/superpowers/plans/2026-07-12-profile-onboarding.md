# Profile Onboarding Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Vendor ai-job-search's `/setup` and `/expand` Claude Code skills into the Job Dashboard project — stripped of its Danish-specific portal skills — and run them against Rakshit's real background to produce the structured profile that the matching engine, resume engine, and cover-letter generation all read from.

**Architecture:** This subsystem is integration/configuration work on a vendored third-party skill set, not new application code — there is no library code to unit-test. Each task's verification step is a file/content assertion or a command's exit status, not a pytest test. The vendored skills live under `.claude/skills/ai-job-search/`, clearly separated from the project's own code (`src/job_dashboard/`, built in the Job Aggregation plan) and from ruflo's existing `.claude/` configuration.

**Tech Stack:** Claude Code skills (Markdown + LaTeX), git (for vendoring via clone + selective copy), a LaTeX distribution (TeX Live or MacTeX) with `lualatex`/`xelatex`, and `pdftotext` (from `poppler`) for the ATS-check step reused later in the Resume Engine plan.

## Global Constraints

- Rakshit's actual resume PDF, LinkedIn export, and any other personal documents go in a `documents/` folder that is **gitignored** — never commit raw personal documents.
- The vendored `ai-job-search` clone itself (`vendor/ai-job-search/`) is a scratch working copy for selective-copying files out of, not something to keep around — gitignore it too.
- Danish-specific portal skills (Jobindex, Jobnet, Jobbank, Jobdanmark) and the LinkedIn/freehire portal skills must **not** be copied into the vendored skill set — the Job Aggregation plan already covers sourcing via JobSpy, free APIs, and (later) Scrapling.
- `/setup`'s profile narrative must **not** be written into the project's root `CLAUDE.md` — that file already holds ruflo's swarm/routing configuration (topology, agent routing tables, memory commands) from the earlier `ruflo init`. Writing profile narrative there would mix unrelated concerns and risks corrupting ruflo's config. Redirect it to `.claude/profile/CANDIDATE.md` instead (see Task 2).
- The generated structured profile files (candidate profile, behavioral profile, writing style, job-evaluation, interview-prep) **are** committed to this repo once produced — this is a private local project, and they're the actual working artifact every other subsystem depends on, same trust level as the design doc already committed.

### Task 1: Vendor ai-job-search's skills, stripped of Danish-specific portals

**Files:**
- Create: `vendor/ai-job-search/` (scratch clone, gitignored)
- Create: `.claude/skills/ai-job-search/` (selective copy)

- [ ] **Step 1: Clone ai-job-search into the scratch vendor directory**

```bash
mkdir -p vendor
git clone https://github.com/MadsLorentzen/ai-job-search.git vendor/ai-job-search
```

- [ ] **Step 2: List the skill directories it ships, to confirm what to keep vs. drop**

```bash

```
Expected: a directory per command (`setup`, `expand`, `rank`, `apply`, `outcome`, `interview`, plus the Danish portal skills and `linkedin-search`/`freehire-search`) — exact directory names may differ slightly from the command names; inspect and match by content if so.

- [ ] **Step 3: Copy the skills to keep into the project, excluding Danish/LinkedIn/freehire portal skills**

```bash
mkdir -p .claude/skills/ai-job-search
for skill_dir in vendor/ai-job-search/.claude/skills/*/; do
  name=$(basename "$skill_dir")
  case "$name" in
    *jobindex*|*jobnet*|*jobbank*|*jobdanmark*|*linkedin-search*|*freehire*)
      echo "skipping portal-specific skill: $name" ;;
    *)
      cp -r "$skill_dir" ".claude/skills/ai-job-search/$name" ;;
  esac
done
```

- [ ] **Step 4: Verify the right skills landed and the Danish/portal ones did not**

```bash
ls .claude/skills/ai-job-search/
```
Expected: directories for `setup`, `expand`, `rank`, `apply`, `outcome`, `interview` (naming may vary — confirm each by opening its `SKILL.md`/instructions file). No directory containing `jobindex`, `jobnet`, `jobbank`, `jobdanmark`, `linkedin-search`, or `freehire` should be present:

```bash

```
Expected: no output (grep finds nothing)

- [ ] **Step 5: Append vendor/documents ignores to `.gitignore`**

```bash
cat >> .gitignore <<'EOF'
documents/
vendor/
EOF
```

- [ ] **Step 6: Confirm the scratch clone won't be committed**

```bash
git status --porcelain | grep "^?? vendor/" || echo "vendor/ correctly ignored"
```
Expected: `vendor/ correctly ignored` (git status shows nothing under `vendor/` because it's now gitignored)

- [ ] **Step 7: Commit the vendored skill set**

```bash
git add .claude/skills/ai-job-search .gitignore
git commit -m "feat: vendor ai-job-search's setup/expand/rank/apply/outcome/interview skills, drop Danish-specific portals"
```

## What this plan does not cover (by design)

- `/rank`, `/apply`, `/outcome`, `/interview` are vendored (Task 1) but not yet invoked or adapted beyond the CLAUDE.md redirect — that happens in the later Matching, Resume Engine, Cover Letter, and Application Tracking plans, all of which read from the profile this plan produces.
- `/add-template` and `/reset` were explicitly not adopted per the design doc's Non-goals.
- Adapting `/apply`'s job-portal search step (it currently expects to call the Danish/LinkedIn/freehire skills this plan just removed) — that adaptation belongs in the Resume Engine plan, once it's clear exactly how `/apply` should instead pull from the Job Aggregation plan's SQLite database.
